# Settings window — UI/UX review

Sauce4Zwift mod "GOTTA.BIKE Sauce Lunatic", `pages/announcer-settings.html`, reviewed at the size Sauce opens it (700×600).
Screenshots referenced below are regenerated by `node scripts/settings-shots.mjs` into `build/shots/` (`NN-name.png` = what a rider sees on open at 700×600, `NN-name-full.png` = the whole page). One correction to the review's own caveat: the 07 "Discord" state was captured with the wrong token prefix and rendered as Anonymous; the harness is fixed, and the state renders (green DISCORD badge, "Signed in as …", Sign out only) — it was not part of what the reviewers saw.

## Executive summary

The owner's instinct is right. The window works — every captured state renders, every form saves, the prompt library and the hosted connection row are genuinely good — but the path a new rider takes through it is wrong at almost every step, and the copy across the five tabs has drifted until it contradicts itself. A rider who installs the mod, opens the overlay, presses the gear, configures a provider and closes the window gets **no commentary at all** (F01): the overlay booted paused and nothing un-pauses it. Before that, they land on the wrong tab (F02), read a sentence that says they must pay when a free option is one click away (F03), and are shown a green "Configured" box that means only "a field has text in it" (F04). None of those four is more than a day's work; together they are the whole first-run experience.

Beyond first run, the things that matter most are: the Help tab describes a design that was migrated away and tells hosted riders their voice selection is ignored (F08); six checkboxes on Data Fields are wired to nothing and the tab never says whose data goes where (F11–F15); unsaved prompt edits are silently discarded by the Voice dropdown (F21–F22); "Manual only" is not manual (F10); and on any of Sauce's light themes the labels vanish (F42). The one **structural** change that would retire the most findings at once is adopting Sauce's own settings anatomy — `.tabbed` header, `.std.button` tiers, theme colour tokens, one scroll container (F23, F24, F35, F40, F41, F42, F44) — but it is not the first thing to do. Do the first-run four, then the copy contradictions, then the structural pass.

## What is already good

Fixes must not regress these:

- **Per-provider field visibility** via `data-provider` and `applyVisibility()` is correct in every state (02/03/04/05); the shared Test Connection row is reused, not duplicated. CLAUDE.md records this once shipping broken — keep the boot test.
- **The hosted connection row** (`renderConnection`, 05/06): three distinct states, a badge that carries its word, the anonymous-token warning, a live "N of M free calls left this month" line. Honest and specific.
- **The amber provider note beside the Voice picker** (`renderPromptProviderNote`, 10-prompts-own-on-hosted.png): contextual, fires only when it applies, names the voice the rider will actually hear. The best-placed line in the window; it is the copy that should survive the de-duplication untouched.
- **Read-only built-ins** use `readOnly`, a dashed border and a "— read only" title: text stays selectable and copyable, and built-in prompts are never copied into the rider's settings.
- **Two-click Delete** that turns the button itself into a red "Really delete?", disarmed by typing. No `confirm()` dialog. Extend it, do not replace it.
- **The update notice and its diff**: inline, dismissible, `createElement`-only for rider-typed text, `+`/`-` gutter doubling the colour, "… N unchanged lines" gaps, a 22em cap. News, not an interruption.
- **The prompt pipeline** already speaks announcer language (`riderLine()`: draft as "sheltered/in the wind", HR only when pinned, gap never a bare signed number, road order preserved). Label fixes must describe this, not regress it.
- **Cost accounting refuses to invent a price**: unpriced models add calls but never dollars; hosted shows an allowance not a spend; counters live in shared global keys so the overlay and settings agree. Only the *presentation* of "unknown" needs to change.
- **Host skeleton is real**: `<html class="settings-page" data-settings-key>`, stock `#titlebar`, `<label><key>` rows bound through `common.initSettingsForm(...)()` with the trailing call. The service-filled `#hosted-model` is correctly kept outside the bound form.
- The Prompts tab lands on a working default voice with a one-line description, so a first-run rider need not touch it.

## Findings

Severity: **blocker** = a rider cannot complete a core task or is misled into a wrong/costly action; **major** = real friction or confusion on a common path; **minor** = polish a careful rider notices; **nit** = taste. Effort: S = under half a day, M = one to three days. Line numbers refer to `pages/announcer-settings.html` (html), `pages/src/announcer.mjs` (mjs), `pages/css/announcer.css` (css) unless stated.

### Blocker

**F01 — Configuring a provider while the overlay is open leaves it paused and still saying "Pick an AI provider"** · window · effort M · lenses: first-run
- **✅ Fixed in v0.8.2 (`e4fa79c`). The boot block is now `startCommentary()`, run from the overlay's `changed` listener on the false→true edge of `isProviderConfigured()`; `commentaryPaused` is honoured so a deliberate pause survives a provider swap. Both edges asserted in `overlay-boot-test.mjs`. The stopgap copy was not needed.**
- *Where:* mjs:100 (`isPaused = true`), :395-401 (placeholder and `isPaused` are only reset inside `if (isProviderConfigured())` at boot), :351-360 (the overlay's `changed` handler for `PROVIDER_SETTING_KEYS` calls only `updateApiStatus()` and `renderCost()`), :308 and :1238 (both firing gates require `!isPaused`); `announcer.html:42`; 03-api-anthropic-configured-full.png and 06-api-hosted-anon-connected-full.png end at a green "Status: Configured" box.
- *Problem:* The gear lives on the overlay, so on every first run the overlay is open while the key is entered. Settings says "Connection successful!", the API dot turns green, and the overlay stays paused with the placeholder telling the rider to do what they just did. Ten ticks of a real pack with `eventDriven` on or off produce zero API calls (reproduced in the stub DOM). The exits are unlabelled: the play icon (tooltip "Resume auto-updates", which presumes it ever ran), reopening the overlay, or the refresh button — which fires one line while leaving auto-updates paused, so the rider hears one sentence and then silence. Add an overlay-boot-test assertion after `settingsStore.set('claudeApiKey', …)` that the placeholder changed and the pause state cleared (the stub's `changed` event exercises the real path). Until the listener fix lands, the settings Status box must say: **"Press ▶ in the announcer window to start."** — a stopgap only.

## How this was reviewed

The page's real HTML, CSS and `announcer.mjs` were run in Chromium at 700×600 (the size Sauce opens the window, 2× scale) through fourteen states — Settings, five AI Provider states (first run, Anthropic, Gemini-compatible, hosted disconnected/anonymous/Discord), five Prompts states (built-in, own editing, own on hosted, update notice with diff open, delete armed), Data Fields and Help — capturing both the viewport and the full scrolled page for each. Eight lenses (first-run, information architecture, layout, copy, states, accessibility, data-and-cost, Sauce fit, plus a prompts-tab pass) produced findings that were merged into 50 clusters; each cluster was then attacked by three independent skeptics who re-read the code, re-ran probes in the harness (focus, contrast, pixel diffs, scroll behaviour, real `common.css` renders for the theme and anatomy findings) and re-rated severity. All 50 survived; the corrections they made are folded into the text above and several first-draft claims were dropped as wrong. Caveats: Sauce's base stylesheet is not in the repo, so the screenshots use an approximation (a shorter titlebar, a 14px base) — pixel positions are approximate, and F27/F40/F44 were re-measured against the real compiled `common.scss`; `<ms>` icons are placeholder glyphs; the window was never opened inside the real Sauce Electron host, so the Windows SAPI voice path and the true Electron titlebar were reasoned from upstream source rather than seen; the 07 "Discord" capture is byte-identical to 06 (Anonymous), so the Discord-connected state was not actually observed.
